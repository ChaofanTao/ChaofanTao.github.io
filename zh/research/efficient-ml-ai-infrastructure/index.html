高效机器学习与 AI 基础设施

大多数效率问题，都始于一个悄悄失效的假设。本文沿着一个模型从设计到部署的生命周期，梳理我们的每项工作分别拆掉了哪个假设。

作者：陶超凡（Chaofan Tao）及合作者 · 最后更新 2026-11-06

效率通常被看作一种交换：牺牲一些质量，换取更少的算力或显存。但在我们的经验里，更大的收益往往来自别处。一个方法之所以失效或浪费资源，常常是因为它依赖的某个假设在设计时合理、如今却不再成立：分词器可以在扩展之前固定下来；网络的每个部分对压缩的承受力都一样；缓存里每个 token 同样重要；同步没有成本；硬件不会故障；最强的教师教得最好。

找到失效的假设往往比修复它更难；诊断一旦准确，修复通常很简单。本页按假设所在的模型生命周期阶段来组织。其中第二阶段的量化工作获得 ACL 2022 杰出论文奖。

本页内容：设计 · 压缩 · 记忆 · 计算与服务 · 迁移 · 贯穿全文的洞察 · 开放问题

1. 设计：分词器不是随意的选择

词表大小是一个扩展维度，而多数模型在这上面投入不足。

经典扩展定律描述损失如何随参数量和数据量变化，却把词表排除在外，于是规模相近的模型往往配着差异很大的词表。Scaling Laws with Vocabulary（NeurIPS）把词表重新放回来：把词表参数从网络其余部分中拆出，用字符而非 token 衡量数据量以便公平比较不同分词器，并采用与词表大小无关的损失。IsoFLOPs 分析、基于导数的方法和损失函数参数拟合三种独立估计得出一致结论。

最优词表背后的机制是一个权衡：词表越大，文本切分出的 token 越少、覆盖的概念越多；但算力有限时，罕见 token 的嵌入很难学好。随着算力增长，平衡点随之移动：词表应随模型增长，但增速慢于模型其余部分，而许多流行模型的词表仍然偏小。数据情况也很关键：数据稀缺时，更小的词表能避免罕见 token 过拟合；训练数据远超计算最优时，更大的词表更有利，同时词表变大也会增加推理开销。可以这样理解最优点：在固定算力预算下，它是让模型读到最多训练文本的那个词表大小。词表太小，同样的文本要切成更多 token，算力花在了 token 数上；词表太大，算力又花在了嵌入层和输出层上。交互式计算器把这些结论变成可直接使用的选择。

2. 压缩：模型的各部分并不一样

压缩在模型最不均匀的地方失效，所以修复的关键是区别对待各个部分。

对 BERT 类编码器有效的量化方法在 GPT 类生成模型上失效，而原因一度不清楚。Compression of Generative Pre-trained Language Models via Quantization（ACL 2022 杰出论文）给出了两点诊断：低精度下词嵌入变得几乎相同，生成模型在选择下一个 token 时无法区分它们；不同模块的权重分布差异很大，同一套量化设置无法同时适配。token 级对比蒸馏让每个 token 的表示靠近全精度教师、并与其他 token 保持区分；模块级动态缩放为每个模块单独学习量化范围。结构化剪枝把同样的思路用于“删减”，学习生成式模型中哪些组件可以移除。

视觉语言模型让不均匀性更加明显，因为两种模态承载信息的方式不同。UPop 在视觉和语言两部分上联合搜索更小的子网络，让每种模态的剪枝比例由学习决定而非人为设定，并交替进行搜索与重训练。CrossGET 在推理时合并冗余 token，用一种模态引导另一种模态的匹配。

3. 记忆：不是每个缓存 token 都重要，但要留后路

长上下文的记忆可以大幅压缩，前提是淘汰既要自适应，又要可回退。

KV 缓存保存此前每个 token 的键和值，在长上下文推理中很快成为显存的主要开销。均匀地丢弃很浪费，因为各层并不相同：D2O 根据各层注意力的集中程度为每层分配预算，并保留召回或合并“与保留内容相似的被丢弃 token”的机制，全程无需微调。UNComp 从信息的角度提问，用矩阵熵作为不确定性信号找出可压缩的部分；同样的分析还揭示了负责信息检索的注意力头和层。

扩散语言模型带来了这个问题的另一种形式：它们在每一步去噪时都要重新编码整个前缀。Prefilling-dLLM 无需重新训练，把前缀分块缓存一次，解码时只使用与查询相关的块和 token。一个小细节很关键：每块开头的起始符（BOS）充当周期性的注意力锚点，有了它，稀疏预填充甚至可以优于稠密注意力。

4. 计算与服务：协调比计算更昂贵

在大规模系统中，瓶颈通常是等待，风险通常是状态丢失。

测试时扩展通过在生成时投入更多算力来提升答案质量，常见做法是小模型起草、大模型校验。ATTS 分析了时间花在哪里，发现主要瓶颈是同步而不是计算本身。它用基于一致性预测在线校准的异步推理取代同步校验，同时在串行和并行两个维度上扩展，并对草稿被拒绝的频率保持统计上的控制。

部署也有一个隐含假设：GPU 不会故障。在多 GPU 张量并行中，单卡故障就可能让整个服务中断。AnchorTP 把权重和 KV 缓存保存在推理进程之外的守护进程中，在剩余 GPU 上以不等宽方式重新切分模型，并规划恢复所需的最少数据迁移。

智能体训练的基础设施。同样的两条经验，在用原生 harness 强化学习训练智能体时表现得更加明显。在 Lego-RL 中，一次训练尝试的几乎全部时间都花在智能体行动上：在沙箱里读文件、改代码、跑测试。尝试时长长且参差不齐，同步批次总要等最慢的那一个；异步调度让新的尝试在有空位时立即开始。训练器在尝试进行中更新权重时，部分 rollout 会暂停生成、加载新权重，并在同一个副本上从缓存的前缀继续，长时间的尝试因此不会作废。启动沙箱的时间主要花在构建镜像上，所以预构建任务镜像、挂载智能体运行时、按需拉取镜像，去掉了大部分等待。有一个刻意的例外：评分工具链被固化进每个镜像，尽管会多花一点时间，因为可复现的奖励比更快的奖励更有价值。智能体强化学习在很大程度上是一个效率与可靠性问题。

5. 迁移：最强的教师不是最好的教师

蒸馏效果最好的时候，是信号与学生能学会的东西相匹配，而不是教师最强的时候。

在大模型蒸馏中，前向 KL 与反向 KL 其实有相同的最优解，也都不表现出通常认为的“寻峰”或“求均值”特性。实际差别出现在训练早期：前向 KL 关注教师分布的头部，反向 KL 关注尾部；自适应 KL 据此为两者加权。PerSyn 基于“更强的模型不一定是更好的教师”这一观察，在生成任何数据之前，先把每个提示分配给学生最容易学会的教师，而不是让所有教师都生成、事后再挑选。

同样的结论在智能体训练中独立出现：来自较弱智能体、锚定环境的轨迹，比更强智能体给出的答案教得更好；而黑盒教师的口头反馈无需暴露 token 概率，也能指导学生。

贯穿全文的洞察

  1. 优化之前，先诊断失效的假设。这里的每个结果，都始于追问现有方法为什么失效，而不是尝试一个更快的变体。原因一旦清楚，修复通常很小。
  2. 不均匀才是常态。层、模块、模态、token、教师各不相同。按层、按模块、按模态、按提示自适应分配预算，在压缩、缓存和蒸馏中反复出现。
  3. 留好后路。可召回的淘汰、保存在可能崩溃的进程之外的状态、在权重更新时也不中断的 rollout，让激进的优化变得安全。
  4. 规模越大，协调越占主导。在测试时扩展、线上服务和智能体训练中，最大的收益都来自消除等待，而不是加速计算。
  5. 效率决定了什么能被学会。算力训练不好的罕见 token 嵌入、学生吸收不了的教师输出，都说明效率不只关乎成本，也关乎模型能学会什么。
