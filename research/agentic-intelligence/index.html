Agentic Coding, Reasoning and Evaluation

Agents learn from a loop, not a dataset. This essay follows that loop, from the environment an agent acts in to the evaluation that tells us whether it improved, and collects what building each part in the open has taught us.

By Chaofan Tao (陶超凡) and collaborators at LegoX · Last updated November 6, 2026

Language models became useful by learning from text. Agents become useful by learning from what happens when they act: a command fails, a test passes, a web page turns out to be the wrong one, a reviewer sends a patch back. That shift moves the hard problems. The model still matters, but so do four things around it: the environment it acts in, the experience it collects there, the signal that turns experience into learning, and the evaluation that tells us whether any of it worked.

Our work on coding agents, multimodal reasoning and benchmarks can be read as a study of that loop. Some projects build one part of it in the open: LegoFlow and SWE-Lego for experience, Lego-RL for learning inside real environments, SWE-Review and SwingArena for review and evaluation. Others ask what breaks when the loop meets images, the web or the physical world. Read together, they point to conclusions no single paper states on its own: the strongest model is rarely the best teacher, verification is the scarce resource, and as agents grow more capable, the integrity of the loop has to be engineered rather than assumed.

1. The environment is part of the agent

Change the harness and you change the agent.

A coding agent never sees a repository directly. It sees what its harness shows it: which files and tool outputs enter the context, when the conversation is compacted, how errors are reported and how the loop continues after a failed command. When we trained with Lego-RL inside three widely used harnesses (OpenHands, Claude Code and OpenCode), the same starting model already behaved noticeably differently in each, before any training. That observation shaped the design. Lego-RL trains inside the unmodified harness instead of a simplified copy, and treats the harness as part of the environment rather than part of the policy.

A natural next question is whether one model can serve many harnesses. Training on rollouts from several harnesses at once came close to the average of separately trained models while narrowing some of the gaps between them. That is encouraging, but every harness in those runs was seen during training; how an agent copes with one it has never seen is still open.

The same idea holds outside code. In multimodal search, the tools are the harness: MMSearch-Plus gives a browsing agent a set-of-mark module to mark, crop and zoom into an image before it searches, and that choice changes which evidence the agent can use at all. In robotics, RoboCodeX makes code the interface between perception and action, which makes behavior inspectable and portable across robot platforms.

2. Experience: what is worth learning from

Teachability is a property of the trajectory, not of the teacher.

Experience starts with tasks the environment can check. LegoFlow mines merged pull requests, rewrites each into a task that does not leak its answer, builds an isolated environment, and keeps it only if the original code fails the tests and the reference fix passes. Passing that check makes a task usable, not valuable, so a static rubric also scores difficulty from the scope of the patch, the logic it adds, the breadth of context it touches, the tests and the detail of the instructions. SWE-Lego mixes real tasks, which bring depth, with synthetic ones made by injecting bugs, which bring breadth; Terminal-Lego turns community Q&A into command-line tasks.

The more surprising lessons concern trajectories, the recorded attempts a teacher agent makes on those tasks. Terminal-Lego found that traces which visibly inspect the environment, act on what they saw and then verify the result teach students far better than traces from stronger agents that jump straight to the answer; in the paper's words, “the best solver is the worst teacher.” LegoFlow found a related pattern inside the reasoning itself: teachers that think briefly on every turn teach less than teachers that reason in depth when a problem calls for it, and most of the benefit comes from discarding the shallowest traces rather than keeping only the longest.

Experience also has an integrity problem. Stronger teachers are better at finding shortcuts: locating the upstream pull request, copying the patch, or reading the fix from Git history. A successful trajectory is not necessarily an honest one. The defenses that worked were layered: an explicit instruction not to look up solutions, enforced by the environment, which rewrites history and restricts network access while the agent runs and restores both only for grading.

What we learned

  • Filter trajectories for grounding and depth, not just for success.
  • Treat leakage as a property of the environment to be removed, not a behavior to be discouraged.

3. Signal: from imitation to verification

Each training signal teaches something different, and a well-aimed signal beats a larger one.

Imitation, done carefully. SWE-Lego shows how far supervised fine-tuning goes when the loss is shaped as carefully as the data. Error masking keeps a whole trajectory in context but takes no gradient on the agent's wrong steps, so the model sees its mistakes without learning to repeat them. A curriculum uses trajectory length as a proxy for difficulty and moves from easy to hard while replaying earlier data. At inference time, a generative verifier that answers “yes” or “no” in text ranks attempts better than a scoring head, because it reuses what the model learned in pre-training.

Reinforcement in the real environment. Outcome rewards from executed tests are honest only if what the trainer optimizes matches what the model actually did. Harnesses rewrite their own history, so a saved transcript is not the token sequence that was sampled; Lego-RL records tokens, probabilities and mixture-of-experts routing at generation time and replays the routing during training. Misalignments here are silent: training runs, curves move, and nothing errors. Difficulty is relative to the current policy, because tasks that always pass or always fail produce no learning signal, and that band shifts as the agent improves. After training, agents read more before editing, reread their edits and run tests more often, at the price of longer interactions. Single-rollout optimization pushes efficiency further by learning from one attempt per task with a learned critic, which has to be warmed up before it can guide the policy.

Beyond pass or fail. Many tasks have no single checkable answer. RLVRR replaces one verifiable “dot” with a chain of reference-based checks on content and style, bringing the efficiency of supervised data into reinforcement learning for open-ended generation. On-policy Verbal Distillation learns from black-box teachers that only return text: their scores rank the student's own partial attempts, good prefixes are kept and weak continuations replaced, which preserves the student's exploration.

The same tension in vision. For reasoning vision-language models, long chain-of-thought SFT and RL turn out to help in different places: SFT on hard, multi-step questions at the cost of verbosity, RL across difficulty levels with concise answers. Every way of combining them that we tried traded one benefit for another instead of adding them, the synergy dilemma. SRPO takes a narrower path: first teach the form of good reflection with data, then reward reflections that are short and actually change the reasoning.

4. Evaluation and review: a mirror that cannot be gamed

As agents improve, evaluation has to be designed like a security boundary.

The same capability that lets a teacher find shortcuts during data collection lets an agent find them during evaluation. Benchmarks therefore need the same discipline as training environments, and ideally more realism. SwingArena (ICLR Oral) moves evaluation into continuous integration: models take turns as patch submitters and as reviewers who write the tests, across several programming languages, with retrieval to cope with long repositories. REAgent (ICSE) treats the issue text itself as a requirement that can be incomplete, and checks and refines it before patching.

Review is where evaluation becomes part of the loop. SWE-Review trains a reviewer agent that explores the repository on its own, traces the root cause, compares its diagnosis with a submitted patch and returns structured feedback, turning one-shot generation into generate, review and revise. Two consequences matter beyond the paper: review trajectories transfer back to issue resolution, and because choosing among attempts is cheaper than generating more of them, a good reviewer makes test-time scaling cheaper.

Multimodal benchmarks face their own shortcut: questions that can be answered without looking. MMSearch-Plus builds questions whose answers depend on fine-grained visual cues carried through repeated searches; most failures come from finding the right page and telling similar events apart, not from the final reasoning step. PhyX shows models leaning on memorized formulas and surface patterns instead of physical understanding, and NAVERO probes how video-language models handle relations that change over time.

5. Beyond the terminal

The loop does not change when the environment becomes physical; the interface does.

RoboCodeX decomposes a high-level instruction, in a tree, into object-centric manipulation steps annotated with affordances and safety constraints, and writes them as code. Code plays the role a harness plays for software agents: it is the layer where behavior becomes explicit, checkable and reusable across robots. PhyX measures the physical reasoning such agents need, and our survey of autoregressive models in vision maps how visual generation, from pixels to tokens to scales, is reaching into embodied settings.

What ties it together

  1. The strongest model is rarely the best teacher. Grounded traces beat stronger solvers in Terminal-Lego, stronger teachers hack more in LegoFlow, and the same mismatch between teacher strength and student learnability motivates routing prompts to the right teacher. What transfers is behavior the student can see and imitate.
  2. Verification is the scarce resource. Verified tasks, verifiers that rank attempts, reviewers that diagnose patches and CI-based arenas are all ways of producing trustworthy judgments. Generation is cheap; trustworthy selection is what scales.
  3. Fidelity is a correctness problem. If the tokens, probabilities or routing the trainer sees differ from what the agent did, learning silently optimizes the wrong thing. Systems engineering and learning are not separable in agentic RL.
  4. Capability amplifies shortcuts. Git history, upstream patches and text-only answers to visual questions are all shortcuts that stronger models find more often. Integrity has to live in the environment and the benchmark, not in the prompt.
  5. Depth beats coverage. Deep reasoning on the turns that need it beats shallow reasoning everywhere; useful reflection beats long reflection; and verbose chains of thought are a cost, not a free lunch.

Open questions

  • Can an agent trained across several harnesses work well in one it has never seen?
  • How should credit be assigned across long trajectories, where a single pass or fail arrives after dozens of actions?
  • What changes when agents must ask users questions and iterate, rather than close a ticket alone?
  • Can supervised and reinforcement signals be combined adaptively, so their benefits add instead of trade off?
  • How do these lessons extend to long-horizon tasks, such as building a repository from a natural-language specification?
