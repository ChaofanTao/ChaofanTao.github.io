Agentic Intelligence

What does a model need beyond the ability to produce an answer, if it is to explore, check its work and improve? My work in multimodal reasoning, robotics and coding agents approaches this question from different directions. Further ahead lie questions about teams of agents and AI that helps improve AI.

By Chaofan Tao (陶超凡) · Last updated November 6, 2026

A detail in an image can determine what to search for. A failed test can overturn a diagnosis. A plausible action can depend on conditions that do not exist in the environment. An agent has to work through these gaps: inspect what is there, choose a next step, and revise its understanding when the result arrives.

Code offers a useful place to study this process because actions, changes and test results leave records. It shares questions with my earlier work on vision, multimodal reasoning and robotics: where the evidence for an action comes from, how errors are discovered, and whether experience helps on the next task. Recent LegoX projects make parts of this process executable and inspectable. I also draw on work from other teams to consider how these lessons might extend to agentic intelligence more broadly.

What the model can do depends on what it gets to see

A coding agent reaches its environment through a harness. The harness determines how files are read, how tool results appear, when history is compacted, and how execution continues after a failed command. If an important error message is truncated, the model has to make its next decision without it. That can change the outcome.

In one Lego-RL evaluation, the same starting model's scores differed by 6.8 percentage points across three harnesses. This motivated training in the harness used for execution, followed by training one model across several harnesses. On the three evaluated interfaces, the shared model approached the average performance of three separately trained models. That supports sharing capabilities across familiar interfaces. Which capabilities survive an unfamiliar tool or environment remains a further question.

Images and robots make the question tangible

MMSearch-Plus asks agents to follow fine visual cues through several rounds of image-text retrieval and cross-checking. Being able to crop a detail and search from it changes what the agent can reason about next. PhyX asks models to connect visible phenomena with physical constraints, while NAVERO tests distinctions between similar actions and relations in video. An incorrect answer may begin with perception, retrieval or reasoning; identifying the point of failure gives a more specific starting point for improvement.

RoboCodeX breaks high-level instructions into operations on particular objects and generates control code, making perception, constraints and actions more explicitly connected. Physical environments also change the cost of feedback: a command can be rerun, but a physical action may be irreversible. Could more autonomous agents learn when to observe and when to act according to the environment? Connecting visual generation and understanding to action raises that question too. Our survey of autoregressive models in vision provides background on those visual models.

A useful example leaves the reasoning available to learn

LegoFlow turns real code changes into executable tasks, checking that the original version fails relevant tests and the reference patch passes. SWE-Lego combines real issues with tasks constructed by injecting bugs, balancing complexity and scale. Once the tasks exist, a harder selection problem begins: which records of attempts are worth teaching from?

Terminal-Lego offers a useful example. Across the teacher and student combinations studied, a stronger solver did not necessarily produce a stronger student. Traces that exposed inspection, action and verification transferred better. For a student, the gap between a sequence of correct commands and a usable method is the evidence that explains each decision.

Length is an imperfect substitute for that evidence. In LegoFlow's experiments, students trained on groups ordered by average reasoning length performed much worse on the shortest group, but gains across the remaining groups quickly flattened. Filtering examples with inadequate analysis helped; adding more text did not promise the same return. The more useful questions are whether a consequential decision has support and whether the agent changes course when new information arrives.

Release details matter here. The LegoFlow-SWE data card explains that a zero reward in the raw release includes both test failures and unscored runs. A reward of one records verifier success, rather than a completed audit for answer leakage. How should a system preserve these distinctions if it collects its own data and updates itself? Treating an environment failure as a reasoning error, or retrieving an existing patch as solving the problem, could teach the next round the wrong lesson.

How does experience become a lasting capability?

Supervised fine-tuning (SFT) learns from demonstrations that may themselves contain mistakes. SWE-Lego retains failed steps as context while excluding them from the imitation loss. The student can still see why an attempt failed and how it recovered. A failure supplies information; whether its actions should be imitated is a separate choice.

Reinforcement learning (RL) updates behavior from outcomes and requires the training record to correspond to the attempt that produced them. Lego-RL captures tokens, probabilities and mixture-of-experts routing during generation, then checks correspondence on the training side. History rewrites still complicate reconstruction. Such problems can hide behind normal training curves: the program runs, while its update may no longer represent the decision that actually occurred.

Tasks without a unique answer need more detailed feedback. RLVRR derives content and style requirements from reference answers; OVD uses a teacher's verbal scores to retain better student-generated portions and replace weaker continuations. In multimodal reasoning, our long-CoT SFT and RL study found that their gains did not simply add in the tested combinations, while SRPO specifically trains concise, useful reflection. These studies make the objective concrete: which behavior should change, and what feedback would reveal that change?

A check should add evidence

A patch can fix the example and miss an edge case. An experiment report can read convincingly without ruling out another explanation. SWE-Review has a reviewer inspect the repository and investigate the issue before judging a candidate patch. We measure both decision accuracy and whether the feedback helps a subsequent repair. The useful contribution is what the review checks that generation left unresolved.

Agreement between two agents does not automatically supply two independent pieces of evidence. With the same material and assumptions, they may miss the same error. Could collaboration be organized around reproducible experiments, counterexamples and traceable sources? Tests and continuous integration in SwingArena, and the explicit requirements in REAgent, provide concrete objects to check.

The evaluation environment needs scrutiny too. SWE-Bench Pro V2 repairs tasks and regrades patches applied to clean containers, echoing the leakage encountered in LegoFlow. More capable exploration can reach defects in grading that earlier systems never exposed. Self-improvement takes this a step further: if the agent can change the evaluation procedure itself, what should establish that it has improved?

Multiple agents: what can a division of work achieve?

A complex goal can involve finding evidence, proposing hypotheses, designing experiments, implementing methods and checking results. Those activities may need different tools, context and working rhythms. Multiple agents can pursue them concurrently and examine each other's work. How they divide the task, what they share and when they combine results all matter.

Towards a Science of Scaling Agent Systems finds that coordination benefits depend on task structure in comparisons with controlled tools and compute. Decomposable tasks can benefit, while strictly sequential tasks can suffer from coordination overhead. Studies of multi-agent failures also identify unclear specifications, misalignment between agents, and problems with verification and stopping. This sharpens the research question: can a team learn how to organize itself, deciding when to explore in parallel and when to converge on a decision?

MELD, from October 2026, moves this question into learning by updating both a team coordinator and individual research agents while keeping the executor fixed. Assignments determine the experience each member receives; what members learn changes the division of work worth trying next. How can an experiment distinguish gains from better individuals, better organization and additional computation?

Shared memory presents a related problem. If one member reports that a method works, others need to know on which data, code version and settings. Should that conclusion be checked again when those conditions change? Can a team share the necessary evidence while preserving different lines of inquiry? These questions connect perception, tools, memory and verification well beyond programming tasks.

AI for AI: can an improvement help produce the next one?

AI for AI studies the use of AI to develop data, training methods, evaluation and computing systems. AlphaEvolve combines program generation, automated evaluation and evolutionary search for algorithm discovery, including improvements to computing infrastructure. The Darwin Gödel Machine modifies the agent's own code and retains different versions for further exploration. They improve different objects, but both make proposing, testing and retaining changes into an ongoing process.

Recursive self-improvement (RSI) asks a further question: can the improvement from this round make the next round of discovery more effective? AIDE², reported in September 2026, modifies its own research code and uses accepted versions in subsequent rounds, reporting successive improvements and transfer to held-out tasks. These experiments make the question testable. They also leave room to examine whether gains come from better search, better memory, or increasing familiarity with a particular task collection.

If agents generate evaluators as well, the source of feedback becomes part of the research. EvalResearchBench studies whether agents can construct cheaper evaluations, finding that the best evaluator on development targets need not remain best on sealed targets. One avenue to investigate is separating the information used to propose changes, select candidates and perform final replication, while adding tasks that never participated in the search. How can this remain reliable without verification consuming the entire gain? That question connects RSI directly to efficiency research.

Questions these connections leave open

  • At the same total budget, how can multiple agents obtain evidence and explore possibilities that a single agent would miss? Can they learn to adjust their division of work to the task?
  • To turn a successful attempt into a lasting capability, should experience enter model weights, external skills or shared memory? Where does each form transfer?
  • After several rounds of improvement, how can we establish that subsequent discovery became more effective, beyond having screened more candidates? How should fresh evaluations and replication be budgeted?
