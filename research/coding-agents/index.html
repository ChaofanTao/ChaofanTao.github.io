Coding Agents, Agentic Data and Agentic RL

By Chaofan Tao (陶超凡), LegoX · Last updated November 3, 2026

Chaofan Tao builds open training recipes for LLM software-engineering and terminal agents at LegoX. The work covers the full loop: verified tasks mined from real GitHub pull requests (LegoFlow), supervised fine-tuning with error masking and a difficulty curriculum (SWE-Lego), environment-grounded trajectories for terminal agents (Terminal-Lego), and reinforcement learning inside unmodified agent harnesses such as OpenHands, Claude Code and OpenCode (Lego-RL). Code, data and models are open.

How do you build verified coding-agent tasks at scale?

A task is only useful for training if the environment can prove it: the buggy version must fail the tests and the reference fix must pass them. LegoFlow's Curator block discovers merged pull requests, rewrites each one as a leak-free task, assembles it in the Harbor task format with an isolated environment, and keeps it only after this fail-then-pass check. Every block (Curator, Tracer, Trainer, Evaluator) is packaged as a plugin skill that a coding agent such as Claude Code or Codex can run.

For the LegoFlow-SWE release, filtering started from more than 700K repositories and 12M candidate pull requests and kept 5,000 verified tasks across 8 programming languages and 20 task tags, or 0.0417% of the pool. GLM-5.2 produced 9,767 rollouts, of which 2,780 passed verification. Under the same teacher, scaffold and budget, LegoFlow-SWE beats SWE-rebench-v2 by 5.8, 1.9 and 1.0 points on SWE-bench Verified, Pro and Multilingual.

Can supervised fine-tuning alone produce a strong SWE agent?

Yes, for open models of 8B to 32B parameters. SWE-Lego combines 32k executable task instances and 18k validated trajectories from real and synthetic sources, masks erroneous steps during training, and orders data by difficulty. In the ablation, the dataset adds 25.6 points, refined SFT adds 3.8, and test-time scaling with a trained verifier adds 6.2, lifting Qwen3-32B from 23.2% to 58.8% on SWE-bench Verified. Trajectories that recover solutions from Git history are filtered out, and results are reported on hack-free images.

Why train RL inside the agent's native harness?

Because the harness changes what the model learns from. The same Qwen3.5-35B-A3B checkpoint scores 64.0, 62.4 and 57.2 on SWE-bench Verified under OpenHands SDK, Claude Code and OpenCode, a 6.8-point spread from the harness alone. Lego-RL trains inside each harness without changing its control flow, keeps token-in/token-out fidelity and history alignment, and replays MoE routing from rollout. Train/inference sampled-token probabilities correlate at r ≥ 0.998, and asynchronous training runs 2.5× faster than synchronous (about 1.9× after compute-throughput correction).

All three runs use the same 2,699 tasks and a 200k context budget for 126 steps. In sampled OpenHands SDK trajectories, the share of runs that reread an edited file rose from 73.6% to 98.1% after training.

Do stronger agents make better teachers?

No. In the Terminal-Lego study, Claude Opus 4.6 is the strongest solver on Terminal-Bench 2.0 (69.4), yet Qwen3-8B and Qwen3-32B students trained on its trajectories reach only 5.6 and 15.5. Students trained on DeepSeek-V3.2 (39.3) reach 10.5 and 20.6. The difference follows the share of actions backed by a relevant prior observation, not the teacher's score.

“The best solver is the worst teacher.” — LegoX, Terminal-Lego

Terminal-Lego turns Stack Overflow problems into more than 15,000 Docker-verified terminal tasks across 90+ technical domains in 13 categories.

How should coding agents be evaluated?

Static pass/fail on a fixed set misses how software is actually built. SwingArena (ICLR 2026 Oral) pairs LLMs as patch submitters and test-writing reviewers inside CI pipelines, over 400+ real GitHub issues in C++, Python, Rust and Go. REAgent (ICSE 2027) treats the issue text itself as a requirement to be checked and refined before patching, and outperforms five baselines on three benchmarks. RL reward design beyond code is studied in RLVRR (ICLR 2026), which turns a single verifiable reward into a chain of reference-based rewards.

FAQ

What is SWE-Lego?

SWE-Lego is a supervised fine-tuning recipe for software issue resolution by Chaofan Tao and collaborators. It combines a dataset of 32k task instances and 18k validated trajectories with error masking and a difficulty-based curriculum. SWE-Lego-Qwen3-8B and SWE-Lego-Qwen3-32B reach 42.2% and 52.6% on SWE-bench Verified with SFT only, and 49.6% and 58.8% with verifier-based test-time scaling (TTS@16), evaluated without Git hacking.

What is Lego-RL?

Lego-RL is a harness-native reinforcement learning framework for coding agents from LegoX. It trains a policy inside an unmodified agent harness (OpenHands SDK, Claude Code or OpenCode) while preserving token-level fidelity and MoE rollout-routing replay. Starting from Qwen3.5-35B-A3B, one training run per harness improves SWE-bench Verified from 64.0, 62.4 and 57.2 to 70.4, 68.2 and 66.6.

Are the LegoX datasets, models and code open source?

Yes. Code is on GitHub (LegoX/SWE-Lego, LegoX/LegoFlow, LegoX/Lego-RL, SWE-Lego/terminal-lego), and datasets and models are on Hugging Face under the Lego-X and SWE-Lego organizations, including LegoFlow-SWE and Terminal-Lego-15k.

Do stronger coding agents make better teachers for distillation?

Not necessarily. In the Terminal-Lego study, Claude Opus 4.6 scores 69.4 on Terminal-Bench 2.0 but its trajectories train weaker Qwen3 students than those of DeepSeek-V3.2 (39.3). Trajectories that visibly inspect, act and verify through the harness transfer best, a property the paper calls environment-grounded supervision.
