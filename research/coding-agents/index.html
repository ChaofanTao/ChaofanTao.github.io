Coding Agents, Agentic Data and Agentic RL

By Chaofan Tao (陶超凡), LegoX · Last updated November 4, 2026

Chaofan Tao works on how to train open LLM coding agents end to end, at LegoX. The focus is the part of the stack that usually stays private: where verified training tasks come from, which agent trajectories are worth learning from, how fine-tuning and reinforcement learning fit the agent tools people actually use, and how agents should be evaluated. The outputs are reusable recipes, open data and infrastructure rather than one-off models.

  • Verified data at scaleReal pull requests and community Q&A turned into executable tasks that the environment itself can check.
  • Training recipesFine-tuning that teaches good debugging habits, and RL that runs inside real agent harnesses.
  • Experimental know-howWhat makes a trajectory worth imitating, and why the strongest agent is not always the best teacher.
  • Open infrastructureAgent-operable pipelines, sandboxed environments and dashboards, released as code and data.

Why does this matter?

Coding agents are now judged by whether they can fix real software, but most strong systems are trained with pipelines that are hard to reproduce: data, environments, training and evaluation are tightly coupled and rarely released. This work breaks that pipeline into reusable blocks, so that others can rebuild, audit and improve each part on its own.

Where does good training data come from?

From real software history, checked by execution. LegoFlow mines merged pull requests and rewrites each one into a self-contained task with its own environment and tests. A task is kept only if the environment proves it: the original code must fail the tests and the reference fix must pass. Terminal-Lego applies the same discipline to command-line work, turning community Q&A into sandboxed tasks.

Know-how: only a tiny fraction of raw candidates survive verification, and filtering for verifiability and for real reasoning in the trajectories matters more than collecting more data.

How should coding agents be trained?

Fine-tuning. SWE-Lego shows that a lightweight, SFT-only recipe can be strong when the data is right: combine real and synthetic tasks, mask erroneous steps so the model does not imitate its mistakes, order training by difficulty, and drop trajectories that peek at Git history for the answer.

Reinforcement learning. Lego-RL trains inside the unmodified harness the agent will run in, such as OpenHands, Claude Code or OpenCode, because the harness decides what the model sees and does. The engineering that makes this work: keep the exact tokens generated during rollout, replay mixture-of-experts routing, run training asynchronously, and make every trajectory inspectable.

What makes a good teacher trajectory?

Visible grounding, not raw strength. The Terminal-Lego study found that trajectories which inspect the environment, act on what they saw and then verify the result transfer best to students, while strong agents that jump straight to the answer leave little to learn from.

“The best solver is the worst teacher.” — LegoX, Terminal-Lego

The practical takeaway is to design the interaction so that the trace contains behavior worth imitating, a shift the paper calls harness engineering.

How should coding agents be evaluated?

Closer to how software is actually built. SwingArena (ICLR Oral) puts models in a continuous-integration loop as both patch submitters and test-writing reviewers across several programming languages. REAgent (ICSE) treats the issue text as a requirement to check and refine before patching. RLVRR (ICLR) carries verifiable rewards beyond code to open-ended generation.

FAQ

What is SWE-Lego?

SWE-Lego is an open supervised fine-tuning recipe for software issue resolution. It shows that a lightweight SFT-only pipeline can train strong open coding agents when the data is right: real and synthetic tasks combined, erroneous steps masked out, training ordered by difficulty, and trajectories that copy answers from Git history removed.

What is Lego-RL?

Lego-RL is LegoX's framework for reinforcement learning inside the unmodified agent harness the model will actually run in, such as OpenHands, Claude Code or OpenCode. It keeps the exact tokens generated during rollout, replays mixture-of-experts routing, trains asynchronously, and makes every trajectory inspectable.

Are the LegoX datasets, code and models open source?

Yes. Code is on GitHub under LegoX and SWE-Lego, and datasets and models are on Hugging Face under the Lego-X and SWE-Lego organizations.

Do stronger coding agents make better teachers?

Not necessarily. The Terminal-Lego study found that trajectories which visibly inspect the environment, act on what they saw and verify the result teach students best, even when they come from a weaker agent. Strong agents that jump straight to the answer leave little behavior worth imitating.
